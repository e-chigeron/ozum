# Intentを変更する

プロジェクトの指示が指定するIntentと、関係する仕様・tests・実装を確認する。新規雛形は `Intent/`、既存プロジェクトは `INTENT.md` も使う。両方あり正本が不明なら、勝手に統合しない。

新しい判断が以前の理由を置き換えるのか、両立するのかを明らかにする。過去の理由が必要なら対象を限定して `git log -p -- <path>` や `git show <commit> -- <path>` を使う。

合意した現在の目的・制約と、それを理解するための理由を現行文書に残す。過去の経緯や未採用案を追記せず、関係する仕様・tests・実装も整合させる。

重要な変更では、変更理由、以前の判断との関係、影響を日本語のコミットメッセージに残す。書式は固定しない。分割・移動では旧パスと移動先を記す。`git log --follow` だけでは分割の全履歴は辿れない。squash時にも必要な理由を最終メッセージへ引き継ぐ。

commitとpushは適用先のプロジェクト指示に従う。メッセージ案を返しただけでは理由がGit履歴へ保存されたことにはならない。
