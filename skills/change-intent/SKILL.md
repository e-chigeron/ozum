# 目的・仕様を変更する

ОЗУМでこの手順が実現する目的は [current-context](../../Intent/current-context.md) と [decision-traceability](../../Intent/decision-traceability.md)。配布先では、そのプロジェクトが指定する関連Intentを参照する。これらのОЗУМへの参照は配布先の実行依存ではない。

プロジェクトの指示が指定するIntentと、関係するFeature Spec・tests・実装を確認する。既存の文書・指示・設定が現在仕様の正本を担うなら別文書へ複製しない。新規雛形は `Intent/`、既存プロジェクトは `INTENT.md` も使い、仕様も既存の配置に従う。正本が不明なら勝手に統合しない。

新しい判断が以前の理由を置き換えるのか、両立するのかを明らかにする。過去の理由が必要ならIntentだけでなく関連仕様・実装を対象に `git log -p -- <path>` や `git show <commit> -- <path>` を使う。

採用した振る舞い・契約、制約、受入条件をFeature Specへ反映し、関連Intentへの参照を置く。目的・制約が変わる場合だけIntentを更新し、現在の目的、望む理由、達成状態を残す。手段だけの変更ではIntent本文の更新を要求しない。現在の判断を理解するための理由は残し、過去の経緯や未採用案を累積せず、関係するtests・実装も整合させる。

候補仕様・比較・Current State等は必要時に生成するProjectionとし、正本として同期保守しない。決定後の実装へはFeature Specと対象コード・tests・実装指示を渡し、通常はIntentの読込や再解釈を要求しない。仕様の矛盾・不足が見つかった場合に検討へ戻る。

重要な変更では、変更理由、以前の判断との関係、影響を日本語のコミットメッセージに残す。書式は固定しない。分割・移動では旧パスと移動先を記す。`git log --follow` だけでは分割の全履歴は辿れない。squash時にも必要な理由を最終メッセージへ引き継ぐ。

Issue・PR・ADRの作成や固定の書式を必須にしない。Issue等への参照は任意であり、重要な判断はIssueがなくても変更差分とコミットメッセージから復元できるようにする。

commitとpushは適用先のプロジェクト指示に従う。メッセージ案を返しただけでは理由がGit履歴へ保存されたことにはならない。
