# 開発手法を見直す

摩擦の発生条件、頻度、影響、現在の回避策を、確認できる証拠とともに整理する。未確認の仮説は観測事実と分ける。

開発プロジェクトで観測した場合は、証拠をそのプロジェクトに保ち、証拠の参照、一般化できる範囲、候補変更、成功条件と取消条件を上流へ渡す。上流の編集まで依頼されていなければ、別リポジトリの手法を直接変更しない。転送形式は指定せず、元の会話全文も要求しない。

上流では `Intent/` と `AGENTS.md`、関係する共通指示・Skills・雛形を確認する。現在の方法で扱えない理由を検討し、必要な箇所だけGit履歴で以前の判断を調べる。

指示や仕組みの追加だけでなく、変更・削除も含めて最小の改善を選ぶ。常時contextと保守負担、既存機能との重複、成功条件と取消条件を示す。採用された目的と方法を現行文書へ反映し、変更理由は日本語のコミットメッセージへ残す。実装とcommitは依頼された範囲で行う。
