# 開発手法を見直す

1. 観測された摩擦を、発生条件、頻度、影響、現在の回避策に分ける。仮説だけの問題は恒久ルールにしない。
2. `METHOD.md` と関係する共通指示、Skill、雛形を読み、既存方針で扱えない理由を確認する。
3. 過去の判断理由が必要な箇所だけGit履歴を調べる。Orcaのsessionやcommentは証拠として参照できるが、正本にはしない。
4. 問題を解消する最小変更を提案し、常時context、認知負荷、保守対象がどれだけ増えるかを示す。Orca既存機能との重複を避ける。
5. 成功条件と、改善を取り消す条件を示す。実装やcommitは依頼された範囲だけ行う。
