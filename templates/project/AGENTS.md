# プロジェクト開発ルール

- `Intent/` は現在有効な目的、望む理由、必要な制約・達成状態の正本。実現手段や変更経緯は置かず、手段だけの変更では更新しない。独立して変わる目的を分け、固定の分類やIDは設けない。
- Feature Specは現在満たすべき振る舞い・契約、必要な制約、検証可能な受入条件の正本。配置の入口は [specs/README.md](specs/README.md)。この文書は開発方法と実行指示を担い、このリポジトリの文書だけで基本規則を理解・保守する。
- SpecはFeature Specの略称。Intentの制約は解を選び直す際にも守る条件、Specの制約は現在採用した解の契約として区別する。技術名の有無だけでは分類しない。文書は複数の役割を兼ねてよく、何の正本かを対象・範囲で判断する。設定が契約を兼ねる場合も、実装に書かれている事実だけで要求を正当化しない。
- 検討時は関連Intentと現行Feature Specを読み、必要なIssue・Git履歴・実装を確認する。Intent同士の競合はファイル順で決めず、両立条件または未確定の判断を明示する。
- 決定時は、依頼・権限に沿って採用した内容をFeature Specへ反映し、目的・制約が変わる場合だけIntentも更新する。提案、Issueの賛意、AIが付けたstatusだけを採用済みの根拠にしない。決定と正本文書への反映が未完了なら、その差を明示する。
- 通常の実装時は対象のFeature Spec、対象コード・tests、この文書等の実装指示を読み、受入条件を満たすよう実装する。Intentを通常の実装コンテキストに含めず、仕様を再解釈して変更しない。矛盾・不足を発見した場合は黙って補わず、関連Intentへ戻って検討する。目的・仕様変更のSkill `change-intent` は、Intent不変の仕様変更にも使う。
- READMEは入口と正本への導線、Skillsは特定作業の手順、実装・testsは仕様の実現と検証、Git履歴は採用した変更と理由を担う。手順・設定が仕様を直接表現していれば別文書へ複製しない。変更理由が必要な場合はIntentだけでなく関連仕様・実装のGit履歴を調べる。Issueは任意の議論・引継ぎ先とし、Issue・PR・ADR作成を必須工程にしない。
- Dashboard・Current State・候補仕様・Next Actions等のProjectionは必要時にIntent・Feature Spec・Git・Issue・実装から生成する一時的なビュー。それ自体に採用判断や正本を変更する効力はなく、削除しても正本を失わず再生成でき、人間が同期保守しないものとする。恒久ディレクトリや生成ファイルを必須化せず、会話や作業環境も正本にしない。
- 現行文書には現在の判断を理解するための情報を残し、過去の経緯や未採用案を蓄積しない。引用・NOTE・Issueの議論だけを採用済みの仕様と扱わない。
- 環境とbuild・test・lintはプロジェクトの既存の仕組みを使い、実行コマンドをこの文書から辿れるようにする。Orca・GitHub・devenvは必須ではない。雛形の構成検査は `bash scripts/verify-project` で実行できるが、製品の検証を代替しない。導入時に製品の検証コマンドを定める。
- 手法の摩擦（開発の進行・判断・品質を妨げる支障や負担）はプロジェクト内に証拠を残す。繰り返す摩擦、影響の大きい摩擦、または手法レビューの依頼がある場合に、ОЗУМへの改善候補を `review-dev-method` で検討する。通常の開発で毎回の提案や上流への送信を義務にしない。
- `change-intent` と `review-dev-method` が利用可能なら該当時に使う。利用できない場合も、この文書の基本規則は外部の共通指示に依存しない。
- 依頼の範囲でローカルのcommit・branch・履歴整理を自律的に行ってよい。作業完了時にはIntentに沿って説明できる意味のあるcommit単位に整理し、日本語のメッセージに変更理由と以前の判断との関係を残す。
- 既存の未コミット変更や他者の変更を巻き込まない。履歴の書換えは自分の未共有履歴に限り、共有済み履歴の書換えには別途合意を得る。
- 明示的なlocal-only指定がなければ、検証と公開確認の後、設定済みupstreamまたは明示された送信先へpushしてよい。remote・認証・対象branchを推測せず、送信先不明や失敗は未同期として報告する。
- push前に送信対象の全commitの差分・メッセージを確認し、一時的な作業履歴、秘密情報、非公開情報が含まれないようにする。公開branchを変えても履歴は公開される。判断できない情報があればその公開を保留して確認する。
