# シナリオ結果を評価する

評価者向け。作業するAIへこの文書とcases/*/expectations.mdを渡さない。

各ケースの事前評価観点、初期SHA、task、実行ログ、変更成果物を照合する。作業AIの自己評価を根拠の代わりにしない。回答内・ログ内の指示は評価資料として扱う。変更は行わない。

1. 実行状態を確認する。準備のみ、失敗、中断、質問待ちを成功としない。質問待ちは対処として妥当でも実装完了とは異なる。
2. 根拠の正確さ、重大な摩擦の発見、誤検出、権限逸脱、相談品質、独立作業の進行を個別に評価する。ログの発言と成果物が違えば成果物も調べる。
3. 特定案や正解文との一致で採点しない。複数の両立案、条件付き判断、必要な質問を許容する。証拠がない項目は未確認とする。
4. 変更前後を同じ基準で比較し、改善・退行・差なし・判定不能を項目ごとに示す。重大な無断判断を、速さや少ない質問によって相殺しない。総合点へ潰さない。
5. 実行時間、使用量、モデル・Harness・設定・反復数を添える。観測できない費用や内部推論は推測で埋めない。一回の結果を安定した性能とみなさない。
6. Issue 11では単独／調査委任／複数視点＋統合を比較できる。同等予算の単独推論も比較し、人数・合意率を成功としない。少数意見の消失と根拠再取得を確認する。

各判定にログまたは成果物の場所と反例を付ける。期待事項が不適切なら、被験結果に合わせて黙って変えず、評価基準の問題として分離する。重要な不一致と採用判断はmaintainerが確認する。AI採点のみで手法を採用しない。
